# 双盘合参（Synastry / 配偶相容性）

## 概述

双盘合参分两层进行：

**层一：Ashtakoota（八大 Koota，传统28分制）**
基于双方月亮星宿，计算8个相容性指标，满分36分。

**层二：Jaimini/Parashari 双盘交叉**
- 双方 DK（配偶指示星）互相激活的宫位
- 双方 UL（伴侣宫）的星座关系
- 双方 A7（Darapada，实际伴侣宫）的对望/同宫关系
- Manglik 检查（双方是否均有或均无）

## 使用流程

### 收集信息
需要双方完整的出生信息：
- 出生日期、时间、地点
- 性别

### 计算

```python
from synastry_pyjhora import calculate_synastry

person1 = {
    'year': ..., 'month': ..., 'day': ...,
    'hour': ..., 'minute': ...,
    'lat': ..., 'lon': ..., 'tz_offset': ...,
    'gender': 'M',  # 'M' 或 'F'
    'chart': chart1,  # calculate_full_chart() 返回的 chart，可选
}
person2 = { ... }

result = calculate_synastry(person1, person2)
```

### 解读结果

Ashtakoota 分数：
- ≥28分（≥78%）：极佳，传统上推荐
- ≥21分（≥58%）：良好，可以考虑
- ≥18分（≥50%）：可接受，需综合其他因素
- <18分（<50%）：需谨慎，应结合其他分析

## ⚠️ 否决条件（优先级高于总分，必须在报告总分之前检查）

> **核心原则（KN Rao 传统）**：总分是参考，否决条件是红线。
> 一对 34 分但触发否决的配对，比 22 分但无否决的更危险。
> **必须先检查否决条件，再报告总分，顺序不可颠倒。**

### 1. Naadi 否决（最高优先级）

**Naadi 满分 8 分，得 0 分时触发否决。**

Naadi 分三类：Aadi（首）、Madhya（中）、Antya（尾）。
两人同属一类 → Naadi Dosha（命运相克），得 0 分。

```
触发条件：Naadi 得分 = 0（同 Naadi）

严重程度分级：
  双方均为 Aadi Naadi   → 最严重（对健康和后代影响最大）
  双方均为 Antya Naadi  → 严重
  双方均为 Madhya Naadi → 严重

输出格式（强制）：
  🚨 Naadi Dosha：双方同为 [X] Naadi，得 0/8 分。
     传统视为对后代和健康有重大隐患。
     即使总分达到 [N] 分，此配对不建议在未充分了解风险前推进。
```

**例外（Naadi Dosha 减轻条件，必须逐项核查）**：
- 双方月亮所在星座的守护星（Rashi Lord）相同 → 部分减轻
- 双方月亮在同一星座（Rashi）→ 部分减轻
- 双方月亮在不同 Pada → 部分减轻
- 若以上任一条件成立，在输出中标注"存在减轻因素：[具体条件]"，
  但**仍保留否决警告，不得因此取消**

---

### 2. Bhakut 降权（第二优先级）

**Bhakut 满分 7 分，得 0 分时触发降权。**

Bhakut 检验双方月亮所在星座的宫位关系（以一方月亮为 1 宫起算另一方月亮的落宫）。
以下"凶象数字对"得 0 分（双向计算，取最低值）：

```
凶象数字对（任一方向触发即降权）：
  2-12 对：财富/损耗失衡，一方积累另一方消耗
  3-11 对：努力/收获不对等，长期积怨
  5-9  对：命运方向相悖（此对在部分流派中有争议，需标注）
  6-8  对：最凶，疾病/危机相互触发

触发时的输出格式：
  ⚠️ Bhakut Dosha：双方月亮形成 [X]-[Y] 凶象数字对，得 0/7 分。
     影响：[对应含义]。
     总分因此下调 7 分，实际参考分 = [总分] 分（含 Bhakut 扣分）。
```

**Bhakut 降权逻辑（与 Naadi 的区别）**：
- Naadi = **否决**：影响后代/健康，属于生理层面的根本不合
- Bhakut = **降权**：影响生活品质和关系模式，可通过双方觉察和努力部分缓解
- Bhakut 得 0 分时，**总分需同时展示两个数字**：
  原始总分（含 Bhakut 0 分）和"如果 Bhakut 满分时的假设总分"，
  帮助用户理解 Bhakut 对总分的影响权重

**Bhakut 减轻条件**：
- 双方月亮守护星（Rashi Lords）互为友星 → 标注"部分减轻"
- Jaimini 层双盘交叉信号强（DK/UL/A7 均正向）→ 标注"深层相容性弥补表层 Bhakut"

---

### 3. Gana 降权（第三优先级）

**Gana 满分 6 分，得 0 分时触发降权。**

Gana 分三类：Deva（天，吉星气质）、Manushya（人，凡人气质）、Rakshasa（鬼，强势气质）。

```
降权触发条件（按严重程度排序）：
  Deva + Rakshasa     → 最严重（0/6），气质根本相悖，长期相处磨合成本极高
  Rakshasa + Deva     → 同上（方向互换，结果一致）
  Manushya + Rakshasa → 较严重（0/6），价值观冲突明显
  Manushya + Deva     → 轻度降分（非 0 分，部分相容）

输出格式：
  ⚠️ Gana 不合：[P1 的 Gana] + [P2 的 Gana]，得 0/6 分。
     含义：[气质差异描述]，日常相处模式存在根本性差异。
     总分参考价值降低，建议重点观察 Jaimini 层信号。
```

---

### 4. 高总分陷阱警告（综合判断规则）

> 以下情况**必须主动告知用户**，不得只报总分：

```
情形一：总分 ≥ 28 但 Naadi = 0
  → 输出："总分 [N]/36 表面优秀，但 Naadi Dosha 已触发否决条件，
           此分数具有误导性。建议以否决警告为主要参考。"

情形二：总分 ≥ 28 但 Bhakut = 0
  → 输出："总分 [N]/36，其中 Bhakut 贡献 0 分（凶象数字对）。
           去除 Bhakut 后实际得分为 [N-7]/29，相当于
           [百分比]%，评级降为 [重新评级]。"

情形三：总分 ≥ 28 但 Naadi + Bhakut 均 = 0
  → 最严重：15 分（Naadi+Bhakut）全部缺失，
            实际有效得分仅 [N]/21，强制标注双重 Dosha。

情形四：总分 < 18 但无任何 Dosha
  → 输出："总分偏低（[N]/36），但 Naadi/Bhakut/Gana 三项无否决，
           低分原因分析：[列出具体失分项]。
           Jaimini 层信号可能弥补 Ashtakoota 的不足。"
```

## 8 项 Koota 权重速查表

| Koota | 满分 | 优先级 | 否决/降权 | 核心含义 |
|:------|:----:|:------:|:--------:|:---------|
| **Naadi** | 8 | 🔴 最高 | 否决 | 健康与后代相容性 |
| **Bhakut** | 7 | 🟠 高 | 降权 | 整体相容和生活品质 |
| **Gana** | 6 | 🟡 中高 | 降权 | 气质/性情匹配 |
| Maitri | 5 | 🟢 中 | — | 月亮守护星友敌 |
| Yoni | 4 | 🟢 中 | — | 本性/性格相容 |
| Tara | 3 | 🔵 低 | — | 命运星宿距离 |
| Vasiya | 2 | 🔵 低 | — | 相互吸引力 |
| Varna | 1 | 🔵 最低 | — | 精神层次 |

> 传统说法"≥18 分可接受"的前提是：**Naadi 和 Bhakut 均不为 0**。
> 若两者任一为 0，此基准线失去参考意义。

## 报告输出顺序（强制）

```
1. 否决条件检查（Naadi → Bhakut → Gana）
2. 高总分陷阱检查（若触发，主动说明）
3. 总分及评级（附注是否含 Dosha 扣分）
4. 8 项明细表（附分值和简评）
5. Jaimini 双盘交叉信号
6. 综合建议（伦理约束框架内）
```

## 报告生成（打包 HTML）

合盘分析完成后，如果用户要求"生成报告""打包"，执行以下两步：

### 步骤 1：格式化为 MD 文件

```bash
# synastry_formatter.py 自动调用 synastry_pyjhora.calculate_synastry()
# 并将结果格式化为三个报告 MD 文件
python scripts/synastry_formatter.py \
    --p1-name "甲方" --p1-dob YYYY-MM-DD --p1-time HH:MM --p1-place "城市名" \
    --p2-name "乙方" --p2-dob YYYY-MM-DD --p2-time HH:MM --p2-place "城市名" \
    --output-dir [工作目录]
```

生成：
- `synastry_overview.md`：否决检查（置顶）+ 总分评级 + 8项Koota明细
- `synastry_jaimini.md`：Jaimini双盘交叉 + 关键指示星对照 + 信号列表
- `synastry_advice.md`：优势/挑战对比 + 实践建议 + 伦理声明

### 步骤 2：打包为 HTML 报告

```bash
python scripts/report_builder.py [工作目录] \
    --type synastry \
    --p1 "甲方姓名" \
    --p2 "乙方姓名" \
    --lang cn
```

合盘报告使用**专用封面**（显示双方姓名 + Ashtakoota 总分/评级），
不包含单人报告章节，不含盲审声明页（合盘分析本质上需要了解双方信息）。

## 伦理约束

- **不做绝对判断**：不说"你们绝对不合适"或"一定要分手"
- **提供双面信息**：同时展示相容性好的方面和需要注意的方面
- **Dosha 的表达方式**：说"存在需要双方觉察和应对的模式差异"，而非"命中注定会失败"
- **尊重选择权**：最终决定权在当事人，占星提供参考视角
- **不预测离婚**：可以指出潜在摩擦点，但不预测婚姻是否会失败
